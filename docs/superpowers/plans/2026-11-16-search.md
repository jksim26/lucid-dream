# Search That Grows With Memory: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Queries split on spaces, a stronger deep-search gate, a measured
test of search quality, then a tantivy keyword index that replaces the scan.

**Architecture:** Query parsing and the gate live in `src/store.rs` next to
today's scan. A new `src/index.rs` owns a tantivy index in
`<root>/.lucid/index/`, rebuilt from the Markdown and refreshed by file
size and modified time. `Store::search` uses the index when it opens and the
scan otherwise. A `search-eval` command scores either engine on a private
question file.

**Tech Stack:** Rust 2021, tantivy (BM25, English stemmer).

**Spec:** `docs/superpowers/specs/2026-11-16-search-design.md`

## Global Constraints

- Markdown in git stays the only real memory; `.lucid/index/` is disposable.
- Output stays `path:line: text`; `search` tool arguments do not change.
- Gate: working memory has found something only when one working file
  matches at least half the query terms, rounded up. A `reason` still opens
  the deep layer and is logged.
- Session records (`.record.md`) never reach a sealed caller.
- No test or fixture in this public repo may contain the user's memory. The
  eval question file lives in the memory folder (`search-eval.tsv`).
- Release only when `cargo test` and `cargo clippy --all-targets -- -D warnings` pass.

## Review Focus

- A query of one quoted phrase: matched exactly, counts as one term.
- A query with only punctuation or quotes (`" "`, `,,`): no terms, no hits, no panic.
- Dream renames or deletes files outside the server: the index drops them on
  the next search.
- Two processes on one memory folder (HTTP server and `serve --stdio`): one
  writes, the other reads or scans; neither errors.
- A corrupt or missing `.lucid/index/`: search falls back to the scan.

### Task 5: tantivy index

**Files:** Create `src/index.rs`; modify `src/store.rs` (dispatch),
`src/main.rs` (`reindex`), `src/doctor.rs` (one line), `Cargo.toml`.

**Interfaces:**
- `pub struct Index`; `Index::open(root: &Path) -> Result<Index, IndexError>`
  takes `.lucid/index/writer.lock` or opens read-only.
- `fn refresh(&self, store: &Store)`: re-index files whose size or modified
  time changed, drop removed files; manifest in `.lucid/index/manifest.json`.
- `fn search(&self, terms: &[String], scope: Scope, sealed: bool, limit:
  usize) -> Result<Vec<Hit>, IndexError>`; `Scope` is `Working`, `All` or
  `Dir(String)`.
- `pub fn pieces(text: &str) -> Vec<(usize, String)>`: split at Markdown
  headings and about every 300 words; first line numbers.
- Fields: `path`, `line`, `deep`, `record`, `stem` (en_stem), `raw`
  (whitespace split, lowercased, surrounding `.,;:()` trimmed). Each term
  queries `raw` boosted 2.0 and `stem`; a quoted term is a phrase on `raw`.
- A hit is the line in the piece holding the most terms.

- [ ] Tests: `pieces` split; stemming ("trading" finds "trade"); `#541`
  matches only `#541`; a file deleted on disk disappears after refresh; a
  sealed caller never gets a record; a second `Index::open` on the same root
  is read-only and searches; a garbage `.lucid/index/` makes `Store::search`
  fall back to the scan.
- [ ] Every existing search test passes through the index too.
- [ ] Run the eval with `--engine index`; it must not score below the scan.
- [ ] Release 0.20.0 as in Task 3.

### Task 6: Meaning search (stage 3)
